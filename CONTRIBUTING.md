# Contributing to the Elastic Email Bash SDK

Thanks for taking the time to contribute! This document explains how to report problems, suggest changes and submit pull requests.

## Before you start: this SDK is generated

Almost everything in this repository (the `ElasticEmail` script, the `ElasticEmail.bash-completion` and `_ElasticEmail` completion files, the `Dockerfile`, `docs/` and most of `README.md`) is generated by [OpenAPI Generator](https://openapi-generator.tech) from the Elastic Email API specification.

This means:

- **Manual edits to generated files will be overwritten** by the next release.
- If an endpoint, model, parameter or description is wrong or missing, the fix belongs in the API specification. Please [open an issue](https://github.com/ElasticEmail/elasticemail-bash/issues/new/choose) describing the problem. We'll fix it upstream and regenerate the SDK.
- Pull requests are most useful for non-generated content: documentation, the scripts in `examples/`, build and CI configuration, and repository tooling.

If you're not sure whether something is generated, open an issue first and ask.

## Reporting bugs

Search [existing issues](https://github.com/ElasticEmail/elasticemail-bash/issues) first. If nothing matches, open a new issue using the **Bug report** template and include:

- SDK version (from the [`VERSION`](VERSION) file or [GitHub Releases](https://github.com/ElasticEmail/elasticemail-bash/releases), e.g. `4.2.0`)
- Bash version (`bash --version`), cURL version (`curl --version`) and OS
- The operation you called and the command you ran (the `--dry-run` output helps)
- The full response body and HTTP status code (add `-i` before the operation name to print response headers)

**Never paste your API key** into an issue, log or code sample. Remove it from `--dry-run` output too.

Questions about your Elastic Email account, sending limits, deliverability or billing aren't handled in this repository. The preferred way to get help is the **chat widget on [elasticemail.com](https://elasticemail.com)**.

Looking for sample code? See the [`examples/`](examples) folder and the [Elastic Email examples repository](https://github.com/ElasticEmail/elasticemail-examples).

## Suggesting features

Open an issue using the **Feature request** template. Describe the use case first and the solution second. It helps us decide whether the change belongs in the API, the SDK or the documentation.

## Security issues

Please do **not** report security vulnerabilities in public issues. See [SECURITY.md](SECURITY.md).

## Development setup

Requirements: Bash 4.3 or later and cURL. [ShellCheck](https://www.shellcheck.net) is recommended for changes to scripts in `examples/`.

```bash
git clone https://github.com/ElasticEmail/elasticemail-bash.git
cd elasticemail-bash
bash -O extglob -n ElasticEmail
./ElasticEmail --host https://api.elasticemail.com --dry-run contactsGet limit=1
```

The client depends only on Bash and cURL. Keep it that way and don't add other runtime dependencies without discussing it in an issue first.

## Pull requests

1. Fork the repository and create a branch from `master` (`git checkout -b fix/short-description`).
2. Keep each change focused. One logical change per pull request.
3. Make sure `bash -n` passes for every script you changed (use `bash -O extglob -n ElasticEmail` for the main script), and that the commands you touched still work (at least with `--dry-run`).
4. Update documentation if your change affects how the SDK is used.
5. Open a pull request against `master` and fill in the template.

A maintainer will review your pull request and may ask for changes. When a change touches generated code, we may apply it upstream instead of merging the PR directly. You'll still get credit in the release notes.
